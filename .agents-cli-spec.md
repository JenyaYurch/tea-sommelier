# Agent Spec

## Overview

**tea_sommelier** — AI-сомелье по **китайскому чаю витрины** (зелёный, белый, жёлтый, красный, шен/шу пуэр, GABA). Зелёный остаётся самой глубокой экспертизой, но не единственным типом. Диалог на русском; факты о сортах/терруаре/заварке только из tools. Витрина `teashop.by` через `find_in_shop`.

Пользователь описывает вкус, опыт или сорт → агент резолвит название в slug → тянет semantic/карточку/сравнение/похожие → отвечает 3 рекомендациями с объяснением «почему» и brewing-подсказкой. `/ask` tea.support — только fallback, если остальные tools не дали данных.

## Example Use Cases

1. **Новичок, мягкий, без горечи, утро.** Агент вызывает `search_teas` (и при необходимости `resolve_tea` + `get_tea_card`). Ответ на русском: ровно 3 сорта, у каждого «почему», температура/граммовка/время из карточки. Цены не называет.
2. **«Сравни Лунцзин и Би Ло Чунь, что мягче».** Сначала `resolve_tea` на оба названия, затем `compare_teas`. Не вызывает `ask_sommelier`. Вывод: кто мягче и почему, по данным API.
3. **«Хочу похожий на сенчу, но китайский».** `search_teas` / `similar_teas` после резолва ближайшего китайского зелёного. Явно говорит, что это китайский аналог, не японская сенча.
4. **«Покажи цену / где купить».** На неделе 1 магазина нет: честно отказывает выдумывать цену и наличие; не называет цифры «из головы».
5. **Неизвестный сорт / опечатка.** `resolve_tea` не находит slug → 1 уточняющий вопрос (алиас, провинция, иероглифы) или `search_teas` по вайбу; не выдаёт случайный чай как точное совпадение.

## Tools Required

Источник знаний: `https://api.thetea.app` (tea.support). Auth: **нет** (Free). Язык API: английский. Русские названия закрывает `resolve_tea`, не `/ask`.

| Tool | API / данные | Назначение |
|---|---|---|
| `resolve_tea` | локальный `data/tea_slugs.json` (white/yellow/green/red/puer/oolong) | рус/en/pinyin/алиасы → slug |
| `search_teas` | `GET /api/v2/semantic` | поиск по вайбу; фильтр по allow-list словаря (не green-only) |
| `get_tea_card` | `GET /api/v2/tea/{slug}` | вкус, заварка, терруар, caffeine, price tier (tier ≠ цена магазина) |
| `similar_teas` | `GET /api/v2/tea/{slug}/similar` | «похожее, но мягче/дешевле» |
| `compare_teas` | `GET /api/v2/compare` | бок-о-бок после резолва slug'ов |
| `ask_sommelier` | `GET /api/v2/ask` | **только fallback**, если остальные tools пустые/ошибка |

Не tools на неделе 1: `find_in_shop`, Telegram, Memory Bank, vector RAG.

## Constraints & Safety Rules

- Специализация: китайский чай витрины (white/yellow/green/red/puer/GABA). Японский чай, кофе, алкоголь — вне специализации. Улун не полный onboard: если карточка/витрина есть — не отказывать.
- Смешанный заказ: строка на каждую позицию через `resolve_tea` + `find_in_shop`; не «ровно 3 рекомендации»; не отказ «только зелёный».
- Нет карточки tea.support (GABA не является `tea_type` API) — «нет данных», не энциклопедия из головы. Заварка только из `get_tea_card`, не green-default 75–80 °C для пуэра/красного/белого.
- Факты (вкус, терруар, сезон, обработка, заварка) — только из tool-результатов. Нет выдуманных slug'ов, урожаев, провинций.
- Цены и наличие магазина не выдумывать. `price tier` из tea.support — не цена в BYN/EUR и не «купить здесь».
- Без медицинских обещаний (лечение, давление, детокс). Кофеин — информационно, при необходимости «это не медсовет».
- `/ask` не использовать, если сработали resolve/semantic/card/compare/similar.
- Секреты (`GOOGLE_API_KEY`) не коммитить.

## Success Criteria

Eval / приёмка недели 1 (pass/fail):

1. Промпт «Сравни Лунцзин и Би Ло Чунь, что мягче» → trajectory содержит `resolve_tea` и `compare_teas`, **не** содержит `ask_sommelier`; ответ на русском называет оба сорта.
2. Промпт «Я новичок, хочу мягкий чай без горечи утром» → есть `search_teas` (и/или card после resolve); в тексте **3** рекомендации, у каждой «почему».
3. `resolve_tea("Лунцзин")` и `resolve_tea("Би Ло Чунь")` возвращают slug'и семейств longjing / biluochun (не пусто, не чужой сорт).
4. Промпт «Сколько стоит Лунцзин?» → нет выдуманной суммы в BYN/EUR/USD; агент говорит, что витрины пока нет.
5. Промпт про лечение болезнию чаем → отказ от мед. обещаний, можно общий brewing/вкус.
6. Ответы пользователю — на русском (поля API могут оставаться en внутри tool).
7. Смешанный заказ (жасмин + шен/шу + Дянь Хун + Дун Дин + Е Шен + Ю Лань Чи Гань) — нет отказа «только зелёный»; строка на каждую позицию; факты только из tools.
8. `resolve_tea` находит Бай Му Дань, Цзюнь Шань Инь Чжэнь, Дянь Хун, шен/шу пуэр; GABA в tea.support отсутствует — `not_found`, не выдуманный slug.

## Architecture & Sub-Agents

- **Неделя 1:** один root `LlmAgent` (`tea_sommelier`) + function tools. Без transfer на sub-agents.
- **Сессии:** in-memory или локальный SQLite (прототип). Не Cloud Run filesystem как прод-хранилище.
- **Деплой недели 1:** нет. Scaffold как **prototype**. Cloud Run + Telegram — неделя 3.
- **Retrieval:** structured HTTP tools + slug JSON. Vector RAG не строить.
- **Модель:** Gemini 2.5 Flash-Lite (стоимость MVP ~$5–25/мес). Если scaffold подставит другую модель — не менять молча; сверить со spec после create.

## Non-Functional Requirements

- Стоимость прототипа в пределах free tier AI Studio / минимальный Gemini.
- Репозиторий: этот каталог `TeaBot` (уже git). Секреты только в `.env` (gitignore).
- Регион прод-деплоя позже: `europe-central2` (из архитектурного документа).
- Аудитория ответов: русскоязычная, Польша/ЕС.

## Edge Cases to Handle

- Русское имя не в словаре, английское/пиньинь есть → резолв по alias.
- tea.support 4xx/5xx/timeout → одна понятная ошибка, не подмена фактов из памяти модели.
- Сравнение >2 чаёв → compare доступных пар или последовательные compare, без `/ask`.
- Пользователь про японский чай → не притворяться экспертом; предложить китайский аналог через tools. GABA/тайваньский улун с карточкой или SKU витрины — не отказывать.

## Assumptions

- Gemini на неделе 1 — Google AI Studio `GOOGLE_API_KEY`; пользователь ещё создаёт ключ (инструкция в чате). GCP Free Trial $300 **не** активируем на неделе 1, чтобы не стартовать 90-дневный таймер до Cloud Run.
- tea.support Free достаточен для прототипа; коммерческие условия API запросим до продакшена.
- Словарь slug'ов собираем запросом `/teas` (без green-only) + типы white/yellow/green/red/puer/oolong; ручная доводка алиасов (Лунцзин, Дянь Хун, шен/шу пуэр, Бай Му Дань). GABA в API нет — не выдумывать slug.
- Анкета опыт→вкус→бюджет→кофеин→посуда на неделе 1 — в instruction root-агента, не отдельный sub-agent.
- Каталог teashop.by на неделе 1 отсутствует → любые цены магазина запрещены.
- Имя scaffold-проекта: `tea-sommelier` (enhance текущего репо `TeaBot`), agent directory как в архитектуре: `tea_agent/`.
